# LONG・DOUBLE確認手順

2026年10月4日。音楽なしの試作。物理キーごとの新しい押下による開始、始点MISS後の途中参加、途中MISS後の復帰、保持中の定期判定PERFECTはユーザー指定による確定仕様。時間窓・空白・加算境界等の数値や方式は未決定事項を検証する仮設定で、最終仕様ではない。

## VS Code / Codexでの反映

前回版を導入済みなら、新しい `long_double_demo.json` と `Editor/GameplayCoreChecks.cs` を追加し、ChartData・RhythmSession・KeyboardLaneInput・SilentChartPlayer・SilentChartView・Editor/SilentChartChecks・Editor/SilentChartSceneSetupの差分を反映する。場所はいずれもZIPのAssets以下。既存Sceneと既存.metaは維持する。新規ファイルの.metaと専用SceneはUnityで生成する。

同梱 `verification` をプロジェクト直下へ置けば、.NET SDK 10で次を実行できる。Unityの自動生成csprojには追加しない。NuGetライブラリは使わず、Unityメニューと同じ実際の判定コードを検査する。

```powershell
dotnet run --project verification/CoreChecks.csproj
```

これは判定コアの検査であり、Unityの描画・Input System・Sceneのコンパイル確認は別途必要。提供環境にはdotnetがなく、このコマンドは `command not found` となった。C#判定チェックの成功とは記録していない。

## 今回の更新だけを反映する場合

LONG/DOUBLE版を導入済みなら、`Assets/KeyboardRhythm/SilentPrototype/RhythmSession.cs`・`Assets/KeyboardRhythm/SilentPrototype/SilentChartView.cs`・`Assets/KeyboardRhythm/SilentPrototype/Editor/GameplayCoreChecks.cs`、README・関連docsを更新する。譜面・Scene・既存.metaの変更は不要。

## Unityでの確認

1. インポート・コンパイル後、`Tools > KeyboardRhythm > Open LONG DOUBLE Test` を選ぶ。判定コア、両方のJSON、イベント保持を自動チェックする。失敗したらConsoleの最初のエラーを確認する。
2. 成功すると `Assets/Scenes/LongDoubleTest.unity` を自動作成して開く。二回目以降は保存済みSceneを開く。
3. Play、Gameビューをクリック、Enterの順で開始する。3秒のカウント後に譜面時刻0になる。ノート・長押しの帯・ラベルはコード生成。手動配置とInspectorの参照設定は不要。

F1は前回の基本24ノート、F2は今回のLONG/DOUBLE譜面へ切り替える。切替時はREADYへ戻るのでEnterで開始する。F5は現在の譜面を再読込・初期化する。フォーカス外れによる停止中は譜面秒も止まるため、LONGの空白テストには使わない。

## 表示と入力

| 表示 | 入力・動作 |
| --- | --- |
| 水色TOUCH | 幅内で新しく1キーを押す。通常幅2以上 |
| 黄色DOUBLE・二重線 | 幅内で異なる物理キーを2つ新しく押す。同じレーンのQ+Aでもよい。0/2、1/2の表示は現在の候補数 |
| 緑色LONG・長い帯 | 開始時に幅内のキーを新しく押し、終端まで幅内を1キー以上保持する。持ち替え可。保持中は頭が判定ラインに留まり、帯が短くなる |
| 紫色SPACE | Spaceの単発FLOOR。通常10レーン上、レーン3・8の中心間に表示 |
| 紫色SPACE HOLD・長い帯 | Spaceの長押しFLOOR。LONGと同じ空白・復帰・加算処理を使用 |

LONGの頭は保持中に緑、無入力中に赤になる。始点MISS後も終端まで赤い頭と短くなる帯を表示し、`LONG: PRESS TO JOIN`（FLOOR_LONGは `SPACE: PRESS TO JOIN`）で新しい押下による途中参加を案内する。参加待ちはActive holdsへ含めず、終端までは完了ノート数にも含めない。各レーンの下のキー表示は上・中・下段の対応を示す。記号キーは従来の仮割当を維持し、Shiftは要求しない。

## 譜面の順番

時刻は**画面のTimeが0になってから**の秒数。Enterからは約3秒を加える。120BPM・16ノート。最終ノート37秒、カウントと結果待ちを含め約41秒で終了する。同じ譜面を繰り返し、成功・失敗を別のプレイで確認する。

| 譜面時刻 | 対象 | 操作例・確認内容 |
| --- | --- | --- |
| 0秒 | DOUBLE、レーン1～3 | Q+Aを同時に押す。同じレーンの異なる物理キーで取得できる |
| 2秒 | DOUBLE、レーン4～6 | R+Tを同時に押す。別レーンの2キーでも取得できる |
| 4秒 | DOUBLE、レーン8～10 | I+Pを押す。別のプレイで1キーだけにしてMISSを確認する |
| 6～8秒 | LONG、レーン3～5 | Dで開始→Gを押してからDを離す。途切れない持ち替えで判定を維持する |
| 9～11秒 | LONG、レーン5～7 | Gで開始。一瞬だけ全キーを離し、すぐHへ移る。SHORT GAPの品質評価が下がり、再保持後のHOLD TICKはPERFECTになることを確認する |
| 12～15秒 | LONG、レーン3～5 | Dで開始→1秒ほど全キーを離す→Gで復帰。MISS・コンボリセット後、加算が再開する |
| 16～20秒＋18秒 | LONG、レーン3～5＋TOUCH、レーン5～7 | DでLONGを開始し、18秒にGを新しく押す。両ノートへ入力を共有できる。Gを以前から保持するだけではTOUCHを取得できない |
| 22～26秒＋24秒 | LONG、レーン3～5＋DOUBLE、レーン5～7 | Dで開始し、24秒にG+Jを新しく押す。GをLONGに共有しながらDOUBLEの2キー条件を満たす |
| 28～31秒＋29～31秒 | LONG、レーン3～5とレーン5～7 | 28秒にDで開始、29秒にGを新しく押して2本目を開始、その後Dを離す。Gで両方を保持できる |
| 32～34秒 | SPACE HOLD | Spaceで開始し保持する。終了時は押したままでも、終端で離してもよい |
| 35秒 | 全幅DOUBLE | 異なる任意の通常キー2つを新しく押す |
| 36秒 | 全幅TOUCH | 任意の通常キーを1つ新しく押す |
| 37秒 | SPACE | Spaceを新しく押す。前のSPACE HOLDから保持し続けるだけでは取得できない |

## 確定条件と試作用の仮設定

| 対象 | 確定条件・今回の仮方式・変更箇所 |
| --- | --- |
| U02：時間窓 | 従来どおりPERFECT ±50ms、GREAT ±100ms、GOOD ±150ms。PrototypeSettingsの各framesを60で割る。境界を含む |
| U03：DOUBLE | 2キーの相互差は50ms以内、各キーともGOOD窓内。悪い方の時間判定を採用。候補は物理キーごとの最新押下を保持し、期限切れを破棄。同じキーの再押下だけでは成功しない。成立後の余分なキーには追加加算なし。doublePairFrames=3 |
| LONG開始・参加（確定／U04） | 以前からの保持だけでは開始しない。同じレーンの別物理キーの新しい押下で開始可。始点MISS後の途中参加、開始済みLONGの途中MISS復帰を許可。新しい1押下で複数LONGを同時開始する扱いは試作上の仮方式 |
| U05：空白 | 100ms未満の空白は復帰時に品質評価を1段階下げる（PERFECT→GREAT→GOOD、GOODで止まる）。100ms以上は無入力区間につき1回MISS。空白評価を定期判定へ引き継がず、再保持後の加算はPERFECT。終端に残る短い空白も1回下げる。longMissGapFrames=6 |
| U06：LONG加算 | 開始成功で+1。その後、予定開始拍から0.5拍ごと。終端と同時の加算はしない。開始が遅れた場合、開始前の加算を遡って付けない。始点MISS後の途中参加には追加の開始判定・加算を付けず、参加時刻以降の予定加算だけを付ける。参加時刻と予定加算が一致すればその時点の加算を含む。無入力中の加算を飛ばし、復帰は次の予定加算から。終点の離す判定・加算はなし |
| U07：低BPM | BPM<120では0.25拍ごと。それ以外は0.5拍。lowBpmThreshold、lowBpmHoldTickBeats、holdTickBeatsで変更。BPM変更・停止イベントは未実行 |
| U08：重複LONG | 各ノートで独立して+1。共有キー1つで2本を保持した場合、同じ拍で合計+2 |
| U09：単発の近接・重複 | 同じ拍でエリアが重なるTOUCH/DOUBLEは読込エラー。近接時は新しい1押下で最も近い単発候補1つを処理。LONGとの共有は可能。FLOORとの重複制約の最終仕様は未決定 |
| U10：コンボ・集計 | 成功イベントで+1、MISSで0。画面P/GR/GD/MはLONGの加算や空白MISSを含む判定イベント数。完了ノート数は別表示。長押しの終了時に過去のMISSを再加算しない |

空白やDOUBLEの間隔は入力のフレームポーリングによる時刻で測る。同一フレーム内の押下は同じ時刻になる。現状では100msの境界を手で厳密に検証しにくいため、境界は自動チェックで確認し、Unityでは明確な成功・失敗・復帰を確認する。音楽同期用の入力イベント時刻と遅延補正は今後対応する。

## 今回の開始・途中参加・復帰を確認する

各項目をF5で初期化して別のプレイで確認する。時刻は画面のTime。新しい譜面を作る必要はない。

| 確認項目 | 現譜面での操作例 | 期待結果 |
| --- | --- | --- |
| 保持済みキーでは開始しない | 6秒より前からFを押し続け、6～8秒のLONGで他のキーを押さない | 始点MISS。保持済みFだけでは途中参加もしない |
| 同レーンの別キーで開始 | Fを6秒より前から保持し、6秒にRを新しく押す | F/Rともレーン4だが、新しいR押下でLONGを開始できる |
| 始点MISS後の途中参加 | 6秒のLONGを押さずに見送り、7秒付近でDを新しく押して8秒まで保持 | 赤いPRESS TO JOIN表示から保持状態へ移り、参加以降の予定判定がPERFECT。始点MISSは残る |
| 始点MISS後に全区間未参加 | 6～8秒のLONGを全て押さずに見送る | 始点MISSは1回。参加待ちで追加MISSを繰り返さず、8秒で表示終了・完了 |
| 終端以降は参加しない | 6秒を見送り、8秒以降にDを押す | 終了済みLONGに保持加算は付かない |
| 途中MISSからの復帰 | 12秒にDで開始→1秒ほど離す→15秒より前にGで復帰 | 空白MISSとコンボ0の後、再保持した予定判定からPERFECT加算が再開する |
| FLOOR_LONGも途中参加 | 32秒のSpace始点を見送り、33秒付近にSpaceを新しく押して34秒まで保持 | 始点MISSを残したまま、参加以降の保持判定がPERFECT |

現試作は途中参加しただけで追加のSTART判定やコンボを付けない。参加時刻以降の予定加算から判定し、過ぎた区間へ遡って加算しない。予定加算と参加時刻が一致すれば、その時点の加算を付ける。終端は参加・定期加算とも対象外。Spaceは物理キーが1つなので、保持済みのままで新しいFLOOR_LONGを開始せず、離して押し直す必要がある。

自動チェックではF保持＋R押下、保持だけの開始・参加拒否、両長押し型の途中参加、入力範囲、予定加算と同時の参加、追加START・遡及加算・終了時MISSの防止、参加後の空白と復帰、2本LONG・TOUCHとの共有を検査する。

## 始点と保持中の判定を分けて確認する

LONG（6～8秒、D）とSPACE HOLD（32～34秒、Space）を別のプレイで少し遅く開始し、始点表示がGREATまたはGOODになることを確認する。各始点の約0.10秒後はGREAT境界、約0.13秒後はGOODの例。入力時刻はフレーム単位で取得するため、表示された始点判定を基準にする。キーを離さず、次の予定加算から `HOLD TICK PERFECT` に変わることを確認する。

| 始点の判定 | 保持中の定期判定 | 120BPM・4拍を途切れず保持した場合の集計 |
| --- | --- | --- |
| PERFECT | PERFECT | P=8、GR=0、GD=0 |
| GREAT | PERFECT | P=7、GR=1、GD=0 |
| GOOD | PERFECT | P=7、GR=0、GD=1 |

上表はそのノート単体の加算分。始点で1回、終端を除く定期加算で7回。画面は譜面全体の累計なので、ノート前後の差を見る。遅い始点でも過ぎた加算を遡って付けない。空白中は定期加算しない。再保持後はPERFECTで加算するが、SHORT GAPによる品質低下や過去のMISSは取り消さない。内部のノート全体のResultは始点・空白の最悪評価を保持するため、定期判定とは区別する。

自動チェックはLONG・FLOOR_LONGの両方で、早い／遅いGREAT・GOOD始点、最初と後続のPERFECT加算、始点カウントの保持、空白後のPERFECT加算とMISS保持を確認する。
